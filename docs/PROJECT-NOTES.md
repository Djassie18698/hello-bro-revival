**Protocol facts:** engine Cocos2d-x 2 + Lua 5.1, libgame.so is 32-bit ARM Thumb WITH symbols. HTTP POST/GET to `/<cgi>` on port 18080 (8080 is taken on user's PC). Replies are XML `<RENLONG code="0">…` (child-element text; some values are attributes, e.g. `<chapinfo currentchap= currentstage=/>`). Lua requests contain raw spaces in the URL, so server wraps http in a net server that %20-encodes the request line. Boot order: xk_r_dir -> rl_r_version(reply must have low `val` e.g. 0.0.1 so no update) -> rl_w_login2 (any Uin/Session accepted, auto-create) -> rl_w_reg2 -> rl_r_randname -> xk_w_dir -> rl_r_mainpage (Cmd 1301/1302; `<user>` 26 fields) -> rl_r_trackpoint (must contain `<activity>` or the loading scene never advances; this triggers rl_r_activity then scene change) -> main menu.
Parser field lists live in PROTOCOL-NOTES.txt. Card element fields: type,id,exp,seq,level,attri,starlevel,newlife,tupo_level,cha_tupo,defence_tupo,attack_tupo,attackadd,defenseadd,attack_add,defence_add,cha_add,status. suitlist: item/id/type. ninjalist: ninja/seq. chipbag: chipitem/num.

**Debug loop that works:** BlueStacks Settings>Advanced>ADB on (user's instance was 127.0.0.1:5556). `HD-Adb.exe` is at `C:\Program Files\BlueStacks_nxt\`; use `MSYS_NO_PATHCONV=1` in Git Bash. `adb install -r` of the patched apk (same keystore) then `monkey -p com.hello.bro.yo`, `input tap 540 1270` = START, screencap+pull to view. The client logs everything to logcat under "cocos2d-x debug info" including "this is no node:X" and "LUA ERROR" -> best way to see why a response is wrong. If the server is run hidden, output is redirected to a log file.
